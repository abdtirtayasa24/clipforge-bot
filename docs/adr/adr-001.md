# ADR-001: Backend layout, Python version and uv tooling

- **Status:** Accepted
- **Date:** 2026-10-19
- **Related:** REQ-015, REQ-016 · T01, T07, T45

## Context

The spec mandates `backend/clipforge/` as the importable package with entrypoints `clipforge.main:app`, `python -m clipforge.workers.main` and `python -m clipforge.discovery_cli`. Development happens on Windows, production on Ubuntu. The product owner chose `uv` for environments and installs, and revised the workflow twice on 2026-10-19: first away from uv project mode, then away from `requirements*.txt` files, ending with `pyproject.toml` as the only dependency file.

## Decision

- Backend lives at `backend/` with the flat package `backend/clipforge/`. Python **3.12** (`requires-python = ">=3.12,<3.13"`).
- `backend/pyproject.toml` is the **only** dependency file: `[project.dependencies]` (runtime) and `[project.optional-dependencies].dev` (tooling). Every direct dependency uses an exact `==` pin.
- Environments are created with `uv venv --python 3.12`; dev/CI install with `uv pip install -e ".[dev]"`, the VPS installs with `uv pip install .`.
- No `requirements*.txt`, no `uv.lock`, no `uv add` / `uv sync` / `uv lock`, no bare `pip`.
- Each VPS release records `uv pip freeze` output in the release log.

## Consequences

- One file to read and edit for dependencies; the same commands work on Windows, Linux and CI.
- Transitive dependencies are not locked: a new transitive release can change a fresh install. Mitigated by exact direct pins, CI running on every push, and the recorded `uv pip freeze` used for rollback.
