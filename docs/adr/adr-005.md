# ADR-005: PostgreSQL-backed job queue with leases and fencing

- **Status:** Accepted
- **Date:** 2026-10-19
- **Related:** REQ-004, REQ-014 · T08

## Context

The spec requires a durable job table, one worker claiming one job at a time, five-minute leases renewed about every 60 seconds, reclaim of expired leases, and protection against stale workers overwriting newer state.

## Decision

- Claim with `SELECT … FOR UPDATE SKIP LOCKED LIMIT 1` over eligible jobs; set a new `lease_token` (uuid4), `lease_version += 1`, `lease_expires_at = now() + 5 min`.
- Every job state write is `UPDATE … WHERE id = :id AND lease_token = :tok AND lease_version = :ver`; zero rows raises `LeaseLost` and the stage aborts.
- A heartbeat renews the lease every 60 s.
- All job writes go through one fenced repository function.

## Consequences

- No Redis/Celery; recovery is automatic after crashes.
- Every code path that mutates a job must hold its lease; concurrency tests with two claimers guard this.
