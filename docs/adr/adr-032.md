# ADR-032: One upload at a time, queued in the Mini App

- **Status:** Accepted
- **Date:** 2026-10-22
- **Related:** REQ-005 · amends ADR-017

## Context

Upload progress lived in the video page's component state. Leaving the page hid a running upload, a refresh lost it, and choosing the file again could start a second upload loop on the same upload. Nothing limited how many uploads the server received at once, so several large files could fill the workspace disk together.

## Decision

- The server receives one upload at a time. A partial unique index (`media_assets_one_receiving_upload`) allows a single `kind = 'upload'` row in state `receiving`; `POST /uploads` answers 409 with the active `upload_id` and `video_id` while one exists.
- `GET /uploads/active` returns the upload being received, and `DELETE /uploads/{id}` cancels it (state `failed`, reason `cancelled`) and removes its staging file. Without a cancel, an abandoned upload would block every later one.
- The queue lives in the Mini App, because the file's bytes exist only on the device until they are sent. A module-level queue outside React uploads files in the order they were added and keeps running across page changes. Its entries (video, file name, size, server upload id), but not the files, are saved in `localStorage`.
- After a reload, entries that were in flight come back as waiting for their file. Choosing the same file again resumes from the server's offset (ADR-017). A paused upload keeps the server's slot, so the queue waits until it is resumed or cancelled.
- The Uploads page (`/uploads`, reached from the Sources page and from the video page) lists every entry with its state and actions.

## Consequences

- Disk use from uploads is bounded by one source at a time.
- Queued files are kept only while the Mini App stays open; after a reload each needs to be chosen again. Keeping multi-GB files in browser storage was rejected because of Telegram WebView storage limits and doubled disk use on the phone.
- An upload abandoned on another device blocks the queue until the administrator cancels it on the Uploads page.
- Migration `010` fails all but the newest upload still receiving when it runs; their staging files under `uploads/` stay on disk and can be deleted by hand.
