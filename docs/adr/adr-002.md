# ADR-002: Alembic executes versioned raw SQL migrations

- **Status:** Accepted
- **Date:** 2026-10-19
- **Related:** REQ-016 · T02, T03, T04, T31

## Context

The spec requires Alembic for migration execution and also names numbered SQL migrations (`001_initial.sql` … `005_settings.sql`, `006_affiliate_links.sql`). Supabase-specific SQL (roles, grants, RLS) is easier to review as plain SQL than as Alembic operations.

## Decision

- SQL lives in `backend/migrations/sql/NNN_name.sql` with a matching `NNN_name_down.sql`.
- Each Alembic revision in `backend/migrations/versions/` is a thin wrapper that executes exactly one SQL file.
- ORM models are hand-written to match; a schema-drift test compares ORM metadata with the migrated database.

## Consequences

- Migrations stay reviewable, Supabase-portable and match the spec's file names.
- No Alembic autogenerate; model and SQL changes must be made together (enforced by the drift test).
