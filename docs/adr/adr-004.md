# ADR-004: Supabase connection mode and TLS

- **Status:** Accepted
- **Date:** 2026-10-19
- **Related:** REQ-016 · T02

## Context

Job leasing uses `FOR UPDATE SKIP LOCKED` inside real transactions. Supabase transaction poolers break server-side prepared statements, and the VPS may lack IPv6 for Supabase's direct host.

## Decision

- Connect through the Supabase **session-mode pooler** (or the direct connection where IPv6 works).
- TLS with `sslmode=verify-full`.
- If a transaction pooler is ever used, psycopg prepared statements are disabled.

## Consequences

- Queue semantics behave as in plain PostgreSQL.
- Session pooler connection limits apply; pools are sized for one API process plus one worker.
