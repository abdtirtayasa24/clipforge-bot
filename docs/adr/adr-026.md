# ADR-026: Typed configurable settings with per-job snapshot

- **Status:** Accepted
- **Date:** 2026-10-19
- **Related:** Should-Have (configurable models, thresholds, durations) · T17, T19, T30, T39

## Context

The spec lists configurable AI models, thresholds and durations as a Should-have; changing settings mid-job must not produce inconsistent results.

## Decision

- One Pydantic `SettingsSchema` defines every tunable key with bounds and defaults: models per capability, `min_score`, `clip_min_s`, `clip_max_s`, `max_clips`, `max_overlap`, timeouts, retry limits, quotas, discovery and affiliate settings.
- Scoring weights are fixed by the spec and are **not** configurable.
- `PATCH /settings` validates against the schema; the worker snapshots resolved settings at claim; changes apply to **new jobs only** and are audited.

## Consequences

- No mid-job drift; invalid values are rejected at the API boundary.
- Adding a setting means updating the schema, defaults migration and Settings UI.
