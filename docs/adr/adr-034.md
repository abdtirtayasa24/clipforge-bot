# ADR-034: A running name for every pipeline stage

- **Status:** Accepted
- **Date:** 2026-10-23
- **Related:** REQ-014 · supersedes the stage list of ADR-006

## Context

ADR-006 records a stage only once it has finished; only ingest also records `ingesting` while it runs. A job's stage therefore names the last finished step, not the running one: a job at `candidates_selected` with status `running` is really rendering, and a failure there looks like a selection failure. The names `rendering` and `uploading` already mean "finished", so they cannot be reused as running names without resuming a crashed job after the step it was in.

## Decision

- Each stage records a running name before it starts and its existing finished name when it ends:

  | Running | Finished |
  |---|---|
  | `ingesting` | `validated` |
  | `extracting_audio` | `audio_extracted` |
  | `transcribing` | `transcribed` |
  | `analyzing` | `analyzed` |
  | `selecting_candidates` | `candidates_selected` |
  | `rendering_clips` | `rendering` |
  | `uploading_clips` | `uploading` |
  | `matching_affiliates` | `affiliate_matching` |

- Finished names are unchanged, so stored jobs, job events, provider usage and the benchmark report keep their meaning.
- A job recorded at a running name resumes that stage, as `ingesting` already did. Migration 011 allows the new names; its downgrade maps each running name to the previous stage's finished name, which resumes the same stage.

## Consequences

- A running or failed job's stage names the step that is actually running or that failed.
- Each stage writes one more `stage_changed` event, so the job timeline shows a running and a finished entry per stage.
- `rendering` and `uploading` stay finished names, which reads oddly next to `rendering_clips` and `uploading_clips`.
