# ADR-003: Async SQLAlchemy with psycopg 3 and separated database roles

- **Status:** Accepted
- **Date:** 2026-10-19
- **Related:** REQ-016 · T02, T04

## Context

The spec stack is SQLAlchemy, psycopg and Alembic on Supabase PostgreSQL, and it requires that the runtime role has no schema-modification privileges.

## Decision

- SQLAlchemy 2.x (typed, async) with psycopg 3.
- Two roles: a migration owner used only by Alembic (`CLIPFORGE_MIGRATION_DATABASE_URL`) and a least-privilege runtime role `clipforge_app` (DML only, no DDL) used by the API and worker.

## Consequences

- A compromised API/worker cannot alter the schema.
- Two connection strings must be managed; role creation is documented in the installation guide.
